### Foundational Systems Projects

Building low-level systems demystifies computing and sharpens architectural thinking. These are harder than modern AI agents and offer superior long-term learning value — and once you understand the low-level systems, high-level apps (including AI agents, "the new CRUD apps") become easier to build.

| Project | Build Path | Resource | Status |
|---------|-----------|----------|--------|
| **Compiler** | Start with a basic interpreter → bytecode → machine code | [Crafting Interpreters](https://craftinginterpreters.com/) | 💡 |
| **Operating System** | Minimal OS running one program at a time → add hardware emulation (monitor, keyboard, mouse) | [Nand2Tetris](https://www.nand2tetris.org/) | 💡 |
| **Database** | In-memory key-value store → persistence → indexing → distributed (sharding, failover) | [MIT 6.5840](https://pdos.csail.mit.edu/6.824/) (formerly 6.824) | 💡 |

**Source:** Larry Wu — "Three foundational software engineering projects."

**Portfolio note:** Don't stop at a GitHub repo. Build an interactive UI so recruiters can visualize and interact with the system you built.

### Why Foundational First

- **Foundational knowledge first** — understanding low-level systems makes high-level applications easier to build.
- **Business value** — technical depth develops the ability to see gaps in existing systems and identify business problems, which is critical for long-term career growth.
- **Differentiation** — moves you beyond basic CRUD apps into complex system design.

Coding Questions
Why does heavy AI code generation erode confidence even when you're shipping?
Back:
You're **borrowing** confidence from the tool — not building your own.

When the AI is gone, the confidence collapses with it.

You ship things but don't know *how* you shipped them → impostor syndrome with real-world evidence to back it up.

Built confidence = understanding every line before it's committed.
Borrowed confidence = output you can't explain.

Coding Questions
What is the correct role for AI in coding, according to the vibe-coding trap note?
Back:
AI as **reviewer**, not **author**.

Rule: your understanding must precede the commit.

- Read every line the AI writes
- If you don't understand a line → ask before moving on
- Never commit code you can't explain

The test: could you reproduce this without the AI? If no — you don't own it yet.

Coding Questions
Why does starting too big when confidence is low create a downward spiral?
Back:
Low confidence → attempt something too hard → fail → confidence drops further → even smaller goals feel out of reach.

The loop: **ambition without evidence → failure → reinforced doubt**.

Starting small breaks the loop by generating **evidence** ("I can do this") before attempting harder things.

Confidence is rebuilt through proof, not through intention.

Coding Questions
What is the mechanism by which small wins rebuild confidence?
Back:
Small win → **proof** you can move forward → generates energy (fuel) → next harder goal feels reachable.

Each success lowers the perceived risk of the next attempt.

The goal of the first win is not mastery — it's proving momentum is possible.

Example: REST API → JWT → OAuth2. Not REST API → distributed systems.

Coding Questions
Why do irregular deep sessions feel like starting over, while daily sessions compound?
Back:
**Irregular sessions:** the topic leaves working memory between sessions → warm-up cost is paid every time → progress feels circular.

**Daily sessions:** topic stays warm → each session starts where the last ended → friction decreases over time.

The compounding is not just knowledge — it's **reduced activation energy**. "Just one lesson" is easy to start. A 5-hour session after a week off is hard to start.

Coding Questions
What is the "start the timer" rule and what does it solve?
Back:
**Rule:** start the timer no matter what — regardless of energy, motivation, or mood.

**What it solves:** the false belief that motivation must precede action.

Motivation follows action, not the other way around. The act of starting — even reluctantly — generates the momentum that sustains the session.

Waiting to feel ready is waiting indefinitely.

The Expertise Reversal Effect (Kalyuga & Renkl, 2010) is the finding that instructional methods beneficial for novices become *harmful* for more advanced learners.

Worked examples reduce cognitive load by providing structure the novice's schema cannot yet supply. But once that schema exists, the same structure becomes redundant — it occupies working memory without adding new information, and *prevents* the active processing that builds deeper understanding.

A learner who should be struggling productively is instead passively tracing steps they already understand.

---

### The mechanism

When a novice studies a worked example, working memory is freed to build schema.

When an expert studies the same example, they already have the schema. The example's steps must still be read and processed — but they generate no new cognitive work. Worse: the scripted path prevents the expert from generating their own, deeper connections.

The structure that was a scaffold for the novice becomes a cage for the expert.

---

### The four-stage transition

| Learner state | Best method |
|---|---|
| New to the concept | Full worked example + self-explanation |
| Partial familiarity | Completion problems (some steps shown, some blank) |
| Comfortable with pattern | Problem-first, example only to verify |
| Fluent | Independent problem-solving only |

**The signal for each transition:** can you predict the next step before reading it? Then you've crossed the threshold.

---

### LeetCode application

This is why watching NeetCode solutions stops working once you've seen a pattern several times. The worked example is doing nothing for you — your schema already contains it. The solution is not watching more solutions. It is solving.

Watching solutions when you're already pattern-familiar is not studying. It is avoiding the discomfort of retrieval failure — which is the mechanism that actually builds fluency.

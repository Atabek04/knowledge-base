There are two ways to get an AI to make an animated video. One asks a video model to paint the pixels. The other asks a coding model to write a program, and the program paints the pixels.

<mark style="background: #FFF3A3A6;">Code-rendered video is video whose every frame is drawn by a program the AI wrote, so the AI acts as the programmer and the render is a mechanical step.</mark>

---

### Two artifacts: source and render

A code-rendered video exists twice.

The **source** is a program: an HTML page with a canvas, a React component, a Python scene, a three.js scene. It says what should be on screen at every moment.

The **render** is the MP4 produced by running that program frame by frame and encoding the frames.

<mark style="background: #ABF7F7A6;">Every change is made in the source and then re-rendered, so fixing a typo or moving an arrow is a one-line code edit, never a regeneration.</mark>

---

### A worked example: the LGTM music video

The music video "LGTM" (2026) shows the split clearly.

- The song was generated by Suno.
- The animation was written by Claude Opus 5.5 in TypeScript and three.js.
- A person directed it: the story, the timing, and repeated rounds of frame-level fix requests.

No video model was involved. Claude never produced a pixel; it produced code that produced pixels.

---

### How the program becomes an MP4

The program is not screen-recorded in real time. A harness asks it for the state at time $t$, captures that frame, and moves on to the next $t$.

That only works when the animation is written as [[A deterministic animation computes every frame as a pure function of time so retiming is a data edit|a pure function of time]], and the capture itself is done by [[Headless browser capture turns a web animation into MP4 by seeking each frame and piping it to FFmpeg|headless browser capture piped into FFmpeg]].

---

### Where the AI's work ends

The coding model writes and revises the program.

It does not decide what the video is for, and it cannot watch the result the way a viewer does. <mark style="background: #FF5582A6;">One-shot prompting produces a working render with no point of view; the quality comes from a human directing and reviewing in rounds.</mark>
